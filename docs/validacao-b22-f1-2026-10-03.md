**Mas há uma precisão a fazer, não uma correção:** `git diff ddf9dfc 8836e95 --
runs/tlc/inv-full/full-TypeOK.out` (checkpoint pós-*merge* da B-21, **antes** de F1,

quanto em `8836e95`, é a mesma execução **antiga**, do modelo **anterior** à revisão do
Achado E (confirmado também pelo próprio commit da Fase 3,
`9a8afd1`: "full não foi executado nesta rodada"). **Isso não invalida a conclusão do
Worker** — o modelo revisado é estritamente menor (já estabelecido:
~5,7-5,8× menos estados em `small`/`medium` nos mesmos parâmetros), então é

para liberar F2: a tendência (modelo menor, mesma cardinalidade de réplicas que já

## 3. O crescimento está dentro do esperado — mas F2 deve custar mais do que F1, e `full` provavelmente continuará inconclusivo para os invariantes que FECHAM (não para os que violam)

O fator ~3,92-3,94× **confirma a parte mais barata** da minha estimativa de risco
"Médio" (§4.2 do plano) — `vivo` é só mais uma dimensão booleana por réplica. **F2 deve
custar mais**, por duas razões concretas, não apenas por precaução genérica:

1. `particaoAtiva` (booleano) + `ladoDe: REPLICAS -> {1,2}` juntos contribuem uma
   dimensão de estado pelo menos tão grande quanto `vivo` sozinho — e `Mesclar`
   acrescenta uma escolha não-determinística adicional (`rf \in ladoVencedor`) que
   `Cair`/`Reviver` não têm equivalente.
2. Diferente de F1 (que, como confirmado em §2, não produz **nenhum** contraexemplo
   novo), F2 **deve** produzir contraexemplos novos de I1/I2/I4 (esse é o objetivo) —
   buscas que terminam **achando uma violação** custam geralmente menos que buscas
   exaustivas que terminam **sem achar nada**, mas a introdução de um gatilho de
   violação genuíno pode também alongar a busca até encontrá-lo, dependendo de quão
   "profundo" o cenário exige (`Particionar` + algumas escritas + `Mesclar` + uma
   leitura posterior).

**Ponto importante que atenua o risco, não documentado ainda:** `full` já estar
inconclusivo para `TypeOK`/`I3`/`I4` (invariantes que **fecham**, exigindo busca
exaustiva para confirmar) **não implica** que `full` ficará inconclusivo para os
**novos contraexemplos reais de I1/I2/I4 sob F2** — TLC para assim que acha **qualquer**
violação, e os contraexemplos já observados neste projeto (3-9 estados, inclusive os de
`full` para `I1`/`I5` nesta própria rodada) são **rasos**, encontrados bem antes de a
busca exaurir o espaço. **Expectativa concreta para a próxima rodada:** mesmo que
`full`/`TypeOK` continue inconclusivo com F2, é plausível que `full`/`I1`,
`full`/`I2`, `full`/`I4` produzam contraexemplos reais em tempo razoável — exatamente o
dado que o catálogo precisa, e exatamente a cardinalidade que corresponde ao cluster
real (recomendação do plano, §2.2). **Risco "Médio" mantido, não revisado para
"Médio-alto"** — mas com essa ressalva registrada para não presumir que a
inconclusividade de `TypeOK` em `full` seja um mau presságio para os invariantes que
realmente importam para o catálogo.
